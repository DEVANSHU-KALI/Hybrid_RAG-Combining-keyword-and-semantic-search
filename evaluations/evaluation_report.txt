ANSWER:
Hybrid retrieval combines keyword search and semantic vector search methods for the same query. Each method generates a candidate document list with its own scores or ranking. Reciprocal Rank Fusion (RRF) then combines these ranked lists rather than raw scores. In RRF, each document gets a contribution based on its position in each result list. This approach is particularly useful when the scales of scores from different retrieval methods differ significantly. By focusing on the rank of documents in both lists, RRF can effectively combine the strengths of both BM25 keyword search and dense vector search, ensuring a balanced integration of their respective evidence.

[2/7] QUESTION: What is the difference between a Bi-Encoder and a Cross-Encoder Reranker, and why are Cross-Encoders not used for initial search over the entire corpus?
ANSWER:
A Bi-Encoder retrieval system embeds the query and document separately, whereas a Cross-Encoder reranker directly models the interactions between the words and context of the query and passage. This direct modeling often improves the ordering among a small set of candidates, especially when several passages share vocabulary but differ in how well they answer the question.

Cross-Encoders are not typically used for initial search over the entire corpus because they are more expensive to apply. Each query-passage pair must be processed, making them less suitable for retrieving a large number of candidates efficiently. Instead, a common approach is to first retrieve a manageable candidate set using methods like BM25, vector search, or hybrid fusion, and then rerank those candidates using a Cross-Encoder. This strategy balances the need for relevance with computational efficiency.

[3/7] QUESTION: What causes hallucinations in Large Language Models, and how does grounded generation in RAG mitigate them?
ANSWER:
Hallucinations in large language models can occur due to several factors, including missing evidence, poor retrieval, ambiguous passages, misleading instructions, or the model adding details that are not present in the retrieved context. 

Grounded Generation in RAG mitigates these hallucinations by integrating an information-retrieval stage with a language-generation stage. Instead of relying solely on the model's internal parameters, RAG searches a collection of documents for relevant passages. These passages are then included in the prompt alongside the question, providing the language model with additional context. By doing so, the model's generation process is grounded in the provided evidence, which helps to ensure that the output is more aligned with the actual information available in the documents. This approach does not automatically guarantee factual correctness, but it significantly reduces the likelihood of hallucinations by ensuring that the model's answers are based on the evidence provided.

[4/7] QUESTION: How do forward propagation, loss functions, backpropagation, and optimizers work together to train a neural network?
ANSWER:
Forward propagation, loss functions, backpropagation, and optimizers work together to train a neural network in the following way:

1. **Forward Pass**: During a forward pass, the neural network processes input data through its layers, transforming input features into a prediction. Each layer applies a learned weight and a nonlinear activation function to the data, ultimately producing an output that is compared to the target value.

2. **Loss Calculation**: A loss function evaluates how well the network’s prediction matches the target value. Common loss functions for classification include cross-entropy, while mean squared error (MSE) or mean absolute error (MAE) are often used for regression tasks. The choice of loss function depends on the task at hand.

3. **Backpropagation**: Backpropagation computes the gradient of the loss with respect to the network’s parameters. It calculates these gradients by propagating the error backwards through the network, starting from the output layer and moving towards the input layer. This process helps to determine how much each parameter contributes to the overall error.

4. **Parameter Update**: An optimizer then uses the gradients computed by backpropagation to update the network’s parameters. Optimizers, such as gradient descent, Stochastic Gradient Descent (SGD), or Adam, use these gradients to adjust the parameters in a way that minimizes the loss function. The goal is to iteratively refine the model’s predictions to better match the desired outputs.

This process is repeated over many batches of examples and epochs (complete passes through the training dataset), continuously improving the model’s ability to make accurate predictions.

ANSWER:
In document chunking, the trade-offs between very large chunks and very small chunks are as follows:

- **Very Large Chunks:**
  - **Retrieval Precision:** They may contain several unrelated ideas, leading to imprecise retrieval.
  - **Context Window:** They can consume more of the model’s context window, potentially limiting the ability to understand the context of individual chunks.

- **Very Small Chunks:**
  - **Context Completeness:** They can remove necessary background information, making it difficult to understand the full context of the document.
  - **Definition-Explanation Split:** Definitions might be separated from their explanations, leading to a loss of clarity.
  - **Table Relationships:** Tables can be split between rows or columns, destroying the relationship between values and their headings, which is crucial for understanding the data presented.

[6/7] QUESTION: What are the common dataset split strategies in machine learning, and why should the test set not be used during development?
ANSWER:
In machine learning, common dataset split strategies typically involve dividing the data into training, validation, and test sets. Here’s a detailed breakdown:

| Split Strategy | Purpose |
| --- | --- |
| **Training Set** | Used to learn the model parameters. |
| **Validation Set** | Assists in choosing configurations like feature selection, hyperparameters, thresholds, and model comparisons. |
| **Test Set** | Provides a final evaluation of the model after all development decisions are made. |

The test set should not be used during development because:

1. **Leakage Risk**: Repeatedly using the same test set for making design decisions can lead to data leakage, where information from the test set influences the training process. This can result in an overly optimistic performance estimate, as the model becomes adapted to the specific characteristics of the test set.

2. **Unrealistic Results**: For time-dependent data, a random split might not be appropriate. Evaluating the model on past data after training on future data can lead to unrealistic performance metrics, as the model might not generalize well to real-world scenarios.

3. **Avoiding Information Leakage**: The test set should remain a pristine, untouched source to provide an unbiased evaluation of the model. Using the test set during development can introduce information leakage, such as including target-derived features or standardizing the entire dataset, which would not be available at the time of actual prediction.

By keeping the test set independent, the evaluation remains a true reflection of the model's performance in the real world.

[7/7] QUESTION: How do Dropout Regularization and Early Stopping help prevent overfitting in machine learning models?
ANSWER:
Dropout Regularization and Early Stopping help prevent overfitting in machine learning models through different mechanisms.

- **Dropout Regularization**: During training, this technique randomly masks (drops out) a subset of activations, discouraging the model from relying on specific pathways. This randomness forces the model to learn more robust and generalized features, reducing overfitting to the training data.

- **Early Stopping**: This technique monitors the model's performance on a validation set during training. It stops the training process early when the validation performance starts to degrade, preventing the model from overfitting to the training data. By halting training before the model's complexity increases beyond what the validation set can handle, early stopping helps ensure that the model generalizes better to unseen data.

Together, these methods address different causes of overfitting and can be combined to improve model robustness and generalization.

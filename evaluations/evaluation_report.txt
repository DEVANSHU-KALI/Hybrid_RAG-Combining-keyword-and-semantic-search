[1/7] QUESTION: How do Hybrid Retrieval and Reciprocal Rank Fusion (RRF) work together to combine BM25 keyword search with dense vector search?
ANSWER:
Hybrid retrieval combines keyword search and semantic vector search methods for the same query. Each method produces candidate documents with its own scores or rankings. Reciprocal Rank Fusion (RRF) then combines these ranks instead of raw scores. In RRF, each document's contribution is based on its position in each result list. This approach is particularly useful when the score scales from different retrieval methods differ, as it avoids one method's scores dominating the final ranking due to their scale. By considering the position of each document in the result lists, RRF provides a fairer way to integrate the results from BM25 keyword search and dense vector search, ensuring that both types of evidence contribute appropriately to the final ranking of documents.

[2/7] QUESTION: What is the difference between a Bi-Encoder and a Cross-Encoder Reranker, and why are Cross-Encoders not used for initial search over the entire corpus?
ANSWER:
A Bi-Encoder retrieval system embeds the query and document separately, while a Cross-Encoder reranker models the interactions between the words and context of the query and passage. This difference often allows Cross-Encoders to improve the ordering among a small set of candidates, especially when several passages share vocabulary but differ in how well they answer the question.

Cross-Encoders are not used for initial search over the entire corpus because they are more expensive to apply. Each query-passage pair must be processed, making it less feasible to use them to retrieve an initial, manageable candidate set from a large collection of documents. Instead, a common approach is to first use a retrieval method like BM25, vector search, or hybrid fusion to get a smaller set of candidates, and then rerank these candidates with a Cross-Encoder.

[3/7] QUESTION: What causes hallucinations in Large Language Models, and how does grounded generation in RAG mitigate them?
ANSWER:
Hallucinations in large language models can occur due to several factors, including:

- Missing evidence: The model may generate information not supported by the available data.
- Poor retrieval: In a RAG system, if the retrieval stage fails to find relevant documents, the model might generate information unsupported by any evidence.
- Ambiguous passages: Unclear or ambiguous text in the context can lead to the model generating incorrect information.
- Misleading instructions: If the user's input is misleading or unclear, the model might generate incorrect or unsupported information.
- Model adding details: The model might create details that are not present in the input or context.

Grounded generation in RAG mitigates hallucinations by:

- Involving an information-retrieval stage: The system searches for relevant documents to support the generated output, which helps ensure that the generated content is grounded in real-world evidence.
- Providing context: By including relevant passages from retrieved documents in the prompt, the model is more likely to generate accurate and supported information.
- Promoting separate evaluation of retrieval and generation: This allows for identifying where failures occur, enabling better mitigation strategies.

While RAG does not guarantee factual correctness, it reduces the likelihood of hallucinations by grounding the generation process in external, fact-checked documents.

[4/7] QUESTION: How do forward propagation, loss functions, backpropagation, and optimizers work together to train a neural network?
ANSWER:
Training a neural network involves a series of steps that work together to iteratively improve the network's predictions. Here’s how forward propagation, loss functions, backpropagation, and optimizers collaborate:

1. **Forward Pass**: During a forward pass, the input features are transformed through layers of the neural network. Each layer applies a learned weight and a nonlinear activation function, ultimately producing a prediction. The loss function then compares this prediction to the actual target value to calculate the error.

2. **Loss Function**: The loss function evaluates the prediction accuracy by quantifying the difference between the network’s output and the desired target. Different tasks may use different loss functions:
   - For regression tasks, common loss functions include Mean Squared Error (MSE) and Mean Absolute Error (MAE).
   - For classification tasks, Cross-Entropy Loss is frequently used.

3. **Backpropagation**: Backpropagation computes the gradients of the loss with respect to the parameters of the network. This involves calculating how each parameter affects the loss, working backward from the output layer to the input layer. The goal is to determine the direction and magnitude of the gradient, indicating how each parameter should be adjusted.

4. **Optimizers**: Optimizers use the gradients computed by backpropagation to update the network’s parameters. The process aims to minimize the loss function. Different optimizers use various strategies to update parameters, such as adjusting the learning rate, momentum, and other hyperparameters. Examples include Stochastic Gradient Descent (SGD), Adam, and RMSprop.

The process of forward pass, loss calculation, backpropagation, and parameter updates is repeated over multiple batches and epochs. This iterative process helps the neural network learn from the data and improve its predictive accuracy over time.

[6/7] QUESTION: What are the common dataset split strategies in machine learning, and why should the test set not be used during development?
ANSWER:
In machine learning, common dataset split strategies typically involve dividing the data into training, validation, and test sets. This separation is crucial for evaluating model performance accurately and avoiding biases that could arise from using the same data for both training and testing.

The test set should not be used during development because doing so can lead to what is known as "test result leaks." When the test set is repeatedly used to make design decisions, it gradually becomes part of the development process. This repeated use can result in an overly optimistic evaluation of the model's performance since the model has been optimized using information from the test set. In essence, using the test set for development compromises its role as an independent evaluation mechanism, leading to unreliable final performance estimates.

To maintain the integrity of the test set, it should be used only once, at the very end, to provide a final evaluation of the model after all development decisions have been made. This practice ensures that the test set remains a true reflection of the model's performance under real-world conditions.
